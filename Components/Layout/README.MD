# Layout

This folder contains the application's shared page layout and the interface used when the connection to the server is interrupted. The initial files were generated by the Blazor template. The navigation, breadcrumbs, and footer components listed below are planned additions based on the original project; documenting them does not create their implementation.

## Files and responsibilities

| File | Purpose |
| --- | --- |
|
 `MainLayout.razor`         | Defines the shared structure for pages that use this layout. The `@Body` placeholder displays the current page's content. This is where the team can add a shared header, navigation menu, and footer. 
 `MainLayout.razor.css`     | Contains scoped CSS for `MainLayout.razor`. Use it to style the layout's containers, spacing, and responsive structure. Application-wide styles belong in `wwwroot/app.css`. 
 `ReconnectModal.razor`     | Defines the interface shown when the browser loses its interactive connection to the Blazor server, including connection status messages and recovery controls. 
 `ReconnectModal.razor.css` | Contains scoped styles for the reconnection interface, such as its overlay, dialog, and status indicators. 
 `ReconnectModal.razor.js`  | Contains the JavaScript that supports the reconnection interface, including its response to connection state changes and recovery actions. 

`NavMenu.razor`       | Defines the responsive navigation bar, brand link, desktop links, and mobile menu. In the original project, it also displays login/profile/admin options, handles logout through `AuthService`, and shows the cart item count through `CartService`. It subscribes to both services’ change events and unsubscribes when disposed. Adapt its branding and links for the pet shop. 

`NavMenu.razor.css`   | Provides scoped navigation styles, including branding, icons, links, active/hover states, and responsive menu rules. Retains sidebar and checkbox-toggle rules, while the current navigation component also uses Bootstrap, inline styles, and an embedded style block.

`Breadcrumbs.razor`   | Displays a breadcrumb trail from an `Items` parameter containing a list of `BreadcrumbItem` objects. Each inactive item links to its URL, while the active item identifies the current page.  

`Footer.razor`        | Displays brand information, social links, catalog/support/policy links, copyright information, and a newsletter form. The form checks email input and duplicate subscriptions, then saves a `NewsletterSubscriber` through `ApplicationDbContext`. Payment icons are visual only and do not implement payment processing. 

## How the files work together

- `Components/Routes.razor` normally selects `MainLayout` as the default layout for application pages. A page can explicitly select a different layout.
- `MainLayout.razor` displays the selected page through `@Body`.
- `Components/App.razor` includes `ReconnectModal` so the application can show connection recovery feedback.
- The reconnection component uses its associated CSS and JavaScript to display and manage that feedback.

## Team guidelines

- Keep the generated layout and reconnection files in the initial project. They provide infrastructure, not completed pet shop features.
- Coordinate changes to `MainLayout.razor` and its CSS because they affect the structure of multiple pages.
- Place individual pages in `Components/Pages` and reusable visual components in `Components/Shared`.
- Keep product, cart, and order business logic outside this folder; use `Services` for that logic.
- Preserve the reconnection files and their references unless the team deliberately replaces that behavior. Interactive server rendering depends on a connection to the server.
